# 下載模型與測能力

> 目的：公平地知道「這個模型在我的任務上有多準、多快」。
> 以下以我們跑過的 Gemma 4 31B 為例，換別的模型做法一樣。

## 1. 從 Hugging Face 下載

### 先準備

- 註冊 HF 帳號，到 Settings → Access Tokens 建一個 **read** 權限的 token。
- 有些模型是 gated（要先在模型頁按同意才能下載），例如 Gemma、Llama。先去模型頁按同意。
- token 放環境變數或 `huggingface-cli login`，**不要寫進腳本**。

### 下載，並釘死版本

```python
from huggingface_hub import snapshot_download

path = snapshot_download(
    repo_id="unsloth/gemma-4-31B-it-unsloth-bnb-4bit",  # 換成你要的
    revision="<40 碼 commit hash>",   # 在 HF 模型頁 Files → History 找
    cache_dir=None,                    # 用 HF_HUB_CACHE 環境變數控制
)
print(path)
```

```bash
export HF_HUB_CACHE=/workspace/hfcache   # 放在會保留的硬碟（見各平台文件）
```

**為什麼要釘 revision（版本編號）**：模型作者會偷偷更新檔案。不釘的話，今天和下個月跑的其實是不同模型，數字沒辦法比。

### 驗證「真的下載完整」

```bash
HF_HUB_OFFLINE=1 python -c "from huggingface_hub import snapshot_download; \
print(snapshot_download('<repo>', revision='<hash>'))"
```

離線模式（不連網）還能找到，才算完整。
⚠️ 有些工具載入時不帶 revision，離線會找不到。解法：在快取的 `refs/main` 檔寫入那個 commit hash。

### 大小參考

- 31B 4-bit：約 18～20 GB
- 31B BF16：約 62 GB
- 26B MoE（混合專家架構）：約 49 GB

## 2. 起一個推論服務（vLLM）

vLLM 是最常用的開源推論引擎，會開一個跟 OpenAI 一樣格式的 API。

```bash
pip install vllm==<鎖定版本>
vllm serve <模型路徑或ID> \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.90 \
  --port 8000
```

常用參數：

| 參數 | 意思 | 建議 |
|---|---|---|
| `--max-model-len` | 一次最多幾個 token | 夠用就好，越大越吃記憶體 |
| `--gpu-memory-utilization` | 用掉 GPU 記憶體幾成 | 0.85～0.92；OOM（記憶體不足）就調低 |
| `--enable-prefix-caching` | 相同開頭的提示只算一次 | 每題都用同一段長提示時一定開，省很多 |
| `--quantization fp8` | 載入時轉 8 bit | 見 06 |
| `--enable-lora --lora-modules name=路徑` | 掛 fine-tune 出來的 adapter | 不用合併就能測 |
| `--enforce-eager` | 關掉 CUDA graph | OOM 時的救命參數，會慢一點 |

測試：

```bash
curl localhost:8000/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"<模型名>","messages":[{"role":"user","content":"你好"}]}'
```

## 3. 怎麼測才公平（我們吃過虧學到的）

1. **版本鎖兩層**：推論引擎和 transformers 都要釘死版本，開跑前先檢查，不對就停。
   - 我們的例子：Gemma 4 要 `vllm==0.27.1` + `transformers==5.14.1`。transformers 5.15 以後，vLLM 會**默默**用錯的設定，**不報錯但答案變差**。
2. **同一台機、同一份題目、同一套程式** 跑「原始模型」和「新模型」，並排比較。別拿上個月別台機器的數字來比。
3. **測前先寫下判準**：例如「準確率 ≥ 95% 才算過」。跑完照判準打 PASS／FAIL，不能看到結果再改門檻。
4. **訓練、測試、上線用的提示要一字不差**。我們曾經訓練時沒給選項清單、測試時給了，結果全崩。
5. **測速度**：
   - 延遲（一張多久）：一次送一題，量 P95（最慢那 5% 的時間）。
   - 容量（每秒幾題，QPS）：一次送很多題，慢慢加壓，找到 P95 還在門檻內的最大 QPS。
   - 測延遲時關掉 prefix cache、不要重複題目，不然數字會太好看。
   - 壓測要 500 題以上才穩，200 題會出現忽高忽低。
6. **限制輸出**：只允許模型回答清單裡的選項（vLLM 的 structured outputs / guided choice），答案不在清單就當錯。

## 4. 我們的實測數字（參考）

| 情境 | 結果 |
|---|---|
| H200，31B BF16，單張圖 | P95 約 1.9～2.3 秒 |
| H200，把長清單放在圖片前面讓 prefix cache 生效 | 單卡容量從 <1 QPS 變 7 QPS（但準確率掉 2～3 個百分點，最後沒採用） |
| 同上，改用 FP8 | 容量只多 3%，瓶頸不在記憶體 |
| 4×5090，FP8，2 份模型 | 15.63 QPS |

結論：**提示怎麼排（能不能共用快取）對速度的影響，比量化大很多。**
