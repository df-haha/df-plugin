# GPU 開機訓練指南（Colab／gputw／RunPod）

> 整理日期：2026-09-28，2026-10-08 補上 10 月的新做法（gputw 免開機取檔、三條停機保險、Colab 訓練、兩平台互斥）。內容來自實際租機跑過的紀錄：Gemma 4 31B 視覺語言模型的推論測試、QLoRA fine-tune、FP8 量化、vLLM 壓測。
> 價格都是「當時實付」，會變動，開機前先看官網。

## 這份在講什麼

租一台雲端 GPU，把 Hugging Face（HF，開源模型下載站）上的模型拉下來，然後：

- **測能力**：丟一批題目看答對幾題、多快。
- **fine-tune（微調）**：用自己的資料再訓練一下。
- **量化**：把模型壓小（16 bit → 8 bit／4 bit），省記憶體、跑更快，但可能變笨一點。

## 先選平台

| 你要做什麼 | 選哪個 | 為什麼 |
|---|---|---|
| 先試一下、跑評測，1 小時內結束 | **Colab** | 已有 Google AI 訂閱就有點數，一行指令開 A100 80GB |

## 做事的固定 8 步（三個平台都一樣）

```
1. 選平台、確認餘額夠跑完整段
2. 開機
3. ⚠️ 開機的同時就掛「停機保險」（見 07；gputw 正式訓練掛三條，RunPod 兩條）
4. 跑 preflight（上機檢查）：scripts/gpu_preflight.py（用 `--min-vram-gb` 設這次需要的顯示卡記憶體）
5. 下載模型，釘死 revision（版本編號）
6. 測能力 / 訓練
7. 收割：結果拉回本機（gputw 機器停了也能從 `/vault` 免開機下載）
8. 停機，而且「回查」確認真的停了
```

第 3 步和第 8 步最容易漏，漏了就是空燒錢。我們出過三次事，最久空轉 7 小時。

同時在兩個平台搶機時：**同一時間只准一邊訓練**，另一邊立刻停（見 01 第 9 節）。

## 哪張卡放得下

以 Gemma 4 31B 為例（我們實測）：

| 用法 | 需要的顯示卡記憶體（VRAM） | 可用的卡 |
|---|---|---|
| BF16（原始 16 bit）推論 | 約 62 GB | A100 80GB、H100／H200、RTX PRO 6000 96GB |
| FP8（8 bit）推論 | 約 32 GB | H100／H200、RTX PRO 6000（A100 不支援 FP8） |
| 4-bit QLoRA 訓練 | 峰值約 25 GB | RTX 5090 32GB 勉強、PRO 6000 很寬 |

粗估法：參數量（B）× 2 = BF16 需要幾 GB；× 1 = 8 bit；× 0.5～0.6 = 4 bit。再留 20～30% 給 KV cache（推論時暫存對話內容的記憶體）。

## scripts/ 說明

| 檔案 | 用途 | 狀態 |
|---|---|---|
| `gpu_preflight.py` | 上機第一件事：驗 GPU 真的能算、bf16、4-bit、VRAM | 實戰原檔（改了標題、結尾訊息，VRAM 門檻預設改成 0 不擋） |
| `gputw_api.sh` | gputw API 小包裝 | 從實戰腳本簡化，本份未重跑 |
| `gputw_vault_fetch.sh` | 機器停了，從 `/vault` 免開機下載＋驗指紋 | 從實戰腳本改寫，用假 API 測過（實戰原檔 2026-10-07 在真機上跑過） |
| `gputw_api_backstop.sh` | 第三條停機保險：只打 API，時間到還沒停就停 | 從實戰腳本改寫，用假 API 測過（實戰原檔 2026-10-06 在真機上掛過） |
| `runpod_api.sh` | RunPod API 小包裝 | 從實戰腳本簡化，本份未重跑 |
| `deadman_template.sh` | 停機保險骨架（開機寬限期、ssh 失聯、限時收割） | 從實戰腳本簡化，用假 API／假 ssh 測過，沒在真機器上跑過 |

金鑰一律放環境變數，不要寫進腳本、不要 commit。腳本會把金鑰寫進只有自己能讀的暫存檔再給 curl，不放在指令參數裡（指令參數別人用 `ps` 看得到）。
