# 量化（8 bit／4 bit）與邊緣部署

> 量化：把模型每個數字從 16 bit 壓成 8 bit 或 4 bit。
> 好處：更省記憶體、可能更快。壞處：可能變笨。**一定要實測才知道掉多少。**

## 1. 幾種量化一次看

| 方式 | 位元 | 要不要校正資料 | 主要用在 | 我們用過 |
|---|---|---|---|---|
| vLLM FP8（線上轉換） | 8 | 不用 | GPU 推論服務 | ✅ |
| bitsandbytes 4-bit（NF4） | 4 | 不用 | QLoRA 訓練、省記憶體推論 | ✅（訓練） |
| GGUF（q4_k_m、q8_0…） | 4～8 | 不用 | llama.cpp／Ollama、CPU、筆電 | ✅（匯出，見 05） |
| INT8（W8A8） | 8 | 通常要 | GPU 推論 | ❌ 卡不支援，沒做 |
| AWQ／GPTQ | 4 | 要 | GPU 推論 | ❌ 刻意不用（見下） |

## 2. 哪張卡能跑什麼

| 卡 | 架構 | FP8 | INT8（vLLM） | 備註 |
|---|---|---|---|---|
| A100 | Ampere | ❌（vLLM 只能退化成 W8A16，只壓權重） | ✅ | 沒有 FP8 硬體 |
| A40／A6000 | Ampere | ❌（同上） | ✅ | 我們判不值得 |
| H100／H200 | Hopper | ✅ | ✅ | |
| RTX 5090／PRO 6000 | Blackwell | ✅（還有 FP4） | ❌ | Blackwell 要 CUDA 12.8+ 的 torch |

compute capability（GPU 世代編號）：vLLM 官方文件寫——FP8 完整運算要 ≥ 8.9（Ada、Hopper 以後）；INT8 W8A8 支援 Turing／Ampere／Ada／Hopper，**10.0 以上（Blackwell）不支援**。
來源：https://docs.vllm.ai/en/stable/features/quantization/int8 、https://docs.vllm.ai/en/stable/features/quantization/fp8

## 3. FP8（我們最常用的 8 bit）

```bash
vllm serve <模型> --quantization fp8
```

- 載入時自動轉，**不需要校正資料**。
- 我們在 H200 上跑 31B 的實測：

| 項目 | BF16 → FP8 |
|---|---|
| 權重大小 | 59 GB → 31.7 GB（-46%） |
| KV cache 空間 | +41% |
| 載入時間 | -47% |
| 實際容量（QPS） | 只 +3% |
| 輸出跟 BF16 不同的比例 | 約 5% |

- 在 PRO 6000 上：跟原版答案一致率 92.5%（我們設的門檻是 95%）→ **判不通過**；吞吐 +21%。

**結論**：FP8 讓大模型「放得進比較小的卡」，但不保證「變快很多」，也不保證「一樣準」。要用就跟 BF16 在同一份題目上成對比。

## 4. 為什麼不用 AWQ／GPTQ／llm-compressor

它們安裝時會把 transformers 升到新版，而新版會讓我們的模型在 vLLM 裡**默默算錯**（見 04 的版本鎖）。
如果你的模型沒這問題，它們是正常選項——一樣要先成對實測。

## 5. 4-bit（bitsandbytes）

- QLoRA 訓練的基礎。Unsloth 的 `*-bnb-4bit` 模型已經預先量化好，下載就是 4-bit。
- 上機先確認 4-bit 真的能算：`gpu_preflight.py` 會實際跑一次 4-bit 前向運算，不是只看 `torch.cuda.is_available()`。
- ⚠️ 我們遇過 26B MoE 模型用 4-bit 載入直接失敗，只能退回 bf16。

## 6. GGUF（給 llama.cpp／Ollama）

見 05 第 4 節。建議：

- 先用 `q8_0` 確認幾乎不掉分，再試 `q4_k_m`。
- 用同一份題目跑 16-bit 和 GGUF 版，比準確率。

## 7. 怎麼測量化有沒有變笨（通用做法）

1. 同一台機、同一份題目，跑「原版」和「量化版」。
2. 看兩個數字：
   - **一致率**：量化版跟原版答一樣的比例。
   - **正確率**：量化版對標準答案的比例，跟原版差幾個百分點。
3. 事先寫好門檻（例如一致率 ≥ 95%、正確率掉 < 1 個百分點）。
4. 另外量速度和記憶體（見 04 第 3 節）。

## 8. 聯發科 NPU（MTK）——⚠️ 我們沒實測，以下是公開資料指路

如果目標是跑在聯發科晶片（手機 Dimensity、Genio 開發板）的 NPU 上：

- **NeuroPilot**：聯發科官方 AI SDK，SDK 要登入下載。https://neuropilot.mediatek.com/
- **LiteRT NeuroPilot Accelerator**：Google 和聯發科合作的新版部署方式，用 LiteRT（原 TFLite）一套 API 跑在 NPU 上，支援 LLM。https://developers.googleblog.com/mediatek-npu-and-litert-powering-the-next-generation-of-on-device-ai/
- **ExecuTorch MediaTek backend**：PyTorch 官方的邊緣部署路線。https://docs.pytorch.org/executorch/stable/backends-mediatek.html
- 公開資料提到的量化組合：A16W16、A16W8、A16W4、A8W8、A8W4（A＝運算時的位元、W＝權重的位元）。
- 社群有人在 MT6989 上跑過 Qwen3、MiniCPM 0.5B～8B。https://genio-community.mediatek.com/t/mtk-npu-llm-deployment-yaml-notes-from-a-hobbyist-engineer/2759

建議順序：先在 GPU 上用 04 的方法測出小模型（1B～8B）的基準分數 → 再轉 NPU 格式 → 用同一份題目比掉多少。
