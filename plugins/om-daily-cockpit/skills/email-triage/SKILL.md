# Email Triage Skill

對收件匣郵件做優先級分類並提供回覆建議。**重要寄件人與團隊成員清單一律取自 oc-config
（`identity` + `team.members` 的 email/alias），不寫死任何姓名。**

## 優先級定義

| 等級 | 標記 | 定義 | 響應時間 |
|------|------|------|----------|
| P0 | 🔴 | 緊急：需立即處理 | 1 小時內 |
| P1 | 🟡 | 重要：今日處理 | 當日 |
| P2 | 🟢 | 一般：本週處理 | 3 天內 |
| P3 | ⚪ | 低優先：可延後或略過 | 視情況 |

## 分類規則

### 🔴 P0 緊急
- **寄件人**：高層（總經理/協理層級）、外部客戶（主旨含「急/緊急」）、政府機關
- **關鍵字**：緊急/急件/立即/馬上、截止/deadline（24h 內）、投訴/客訴/異常、停工/停業/違規

### 🟡 P1 重要
- **寄件人**：直屬主管、跨部門主管、重要合作夥伴、**`config.team.members` 內任一成員**（屬下回報）
- **關鍵字**：請協助/請處理/請確認、會議/報告/進度、合約/採購/報價、週內截止

### 🟢 P2 一般
- **寄件人**：同事、一般供應商
- **關鍵字**：FYI/供參考/知會、建議/提案、一週後截止

### ⚪ P3 低優先
電子報/Newsletter、系統通知、廣告促銷、CC 知會（非主要收件人）

## 重要寄件人辨識（config 驅動）

- **團隊成員**：比對寄件人 email 與 `config.team.members[].email` + `alias_allowlist`（**嚴格 email 比對**優先；
  退而求其次才比對顯示名後綴，避免同名誤判）。
- **高層/外部**：用上述職稱/網域線索，不寫死特定姓名。

## 輸出格式

```markdown
## 郵件分類結果
### 🔴 P0 緊急（X 封）
| 主旨 | 寄件人 | 重點 | 建議行動 |
### 🟡 P1 重要（X 封）
| 主旨 | 寄件人 | 重點 | 建議行動 |
### 🟢 P2 一般（X 封）
| 主旨 | 寄件人 | 重點 |
### ⚪ P3 略過（X 封）
- 已過濾：電子報 X 封、系統通知 X 封
```

## 回覆建議模板

- **確認收到**：「收到，我會在 [時間] 前處理完畢。」
- **需更多資訊**：「感謝來信。為處理此事，需請教：1. … 2. …」
- **轉交處理**：「此事已轉交 [負責人] 處理，他/她會直接與您聯繫。」
- **婉拒**：「感謝提案/邀請。經評估目前暫不適合 [原因]，未來有機會再合作。」

## 與 cockpit 整合

- 報告只顯示 P0/P1（最多 5 封）+ 對 P0/P1 提供回覆建議；P2/P3 顯示統計數字。
- **團隊日報的擷取與分析由 `team-daily-fetcher` skill 負責**，本 skill 不重複處理（僅在 P0-P3 分類中把屬下日報歸入 P1）。
