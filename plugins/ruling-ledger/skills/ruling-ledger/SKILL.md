# 裁決帳本（ruling-ledger）

帳本是本 repo 立場的唯一權威。索引 `docs/裁決帳本.md` 永遠載入；詳情 `docs/裁決/R-NNNN.md` 碰到關鍵字才讀。
**索引只是路由與最低警示，不是主防線；判斷一律以詳情為準。**
**Claude 只提議，使用者確認才寫。任何寫入帳本的步驟前都要看到使用者的明確同意（「好」「可以」「記」）。**
**立場不寫進 CLAUDE.md。** 最高層級是索引最上方的「## 0. 硬禁區」段。

## 腳本位置

`<plugin-root>/scripts/ledger_check.py`、`<plugin-root>/scripts/ledger_init.py`。
`<plugin-root>` 優先取環境變數 `CLAUDE_PLUGIN_ROOT`；沒有就從本檔位置往上三層。
範例：本檔路徑 `plugins/ruling-ledger/skills/ruling-ledger/SKILL.md` 往上三層是 `plugins/ruling-ledger/`（內含 `scripts/`），往上兩層只到 `plugins/ruling-ledger/skills/`（無 `scripts/`），對不上要重算。
執行一律 `python "<絕對路徑>" "<repo_root>" ...`，路徑加引號。

## 必讀詳情的三個時機

1. `check` 有任何命中 → 判定前先 Read 該 R 的詳情檔。
2. 要改寫白名單內的檔案，而該檔含索引任一關鍵字 → 動筆前先 Read 對應詳情檔。
3. `add`（新增或改狀態）→ 起草前先 Read 相近項的詳情檔。

這三步是流程的第一步，不靠自己想到。

## init

1. 找 repo 根（有 CLAUDE.md 或 .git 的最近上層）。
2. `python ledger_init.py "<repo_root>" --dry-run` 給使用者看會做什麼。
3. 使用者同意後不帶 `--dry-run` 跑一次；回報 JSON 與備份路徑。
4. 提醒：白名單 A 段是空的，請使用者指名「現在算數的檔案」，用 Edit 填表；已知含舊口徑的檔登進「### 已淘汰檔」子表。

## add（新增或改狀態）

觸發：`/ledger add ...`、「記為打掉／採用」、「這條翻案」、或每輪結尾的裁決變更候選。

1. 讀索引；若命題已有相近項（同關鍵字或同主題）→ **先 Read 該項詳情檔**，走「改狀態」，否則「新增」。
2. 起草，逐欄填：ID（B、C 段最大值 +1）、狀態、命題（一句完整命題，不是關鍵字）、範圍、理由（使用者的原話）、同義表達（打掉項必填）、重審條件（打掉項必填）、出處（session 前 8 碼＋時間）。索引該行的層級填 0、復活填 0、最近復活留空。
3. 把草稿整段貼給使用者，問一句「這樣記可以嗎？」**停下等使用者回。**
4. 使用者說好 →
   - 新增：用 Write 建 `docs/裁決/R-NNNN.md`（照 `templates/R-0000.md`），用 Edit 在索引 B 段表尾加一行（七欄）。
   - 改狀態：Edit 詳情檔的「狀態」行，沿革追加 `- YYYY-MM-DD 改為 X（原話）`；Edit 索引該行狀態。
5. 跑 `ledger_check.py "<repo_root>" --lint`，必須退出 0 才算完成。
6. 回一句：「已記 R-NNNN（狀態）。」

## 每輪結尾的裁決變更報告

只要該輪改到策略內容（白名單檔、帳本命題涉及的檔、或使用者對立場表態），回覆最後固定一行：

- 沒有 → `裁決變更：無`
- 有 → `裁決變更：候選 R-NNNN（狀態）命題…，要記嗎？` 然後停，等使用者回，再走 add 第 4 步。

純錯字、排版、路徑修正不報。

## check

1. `python ledger_check.py "<repo_root>"`（要掃草稿目錄時加 `--scan "<路徑1>" "<路徑2>" ...`，可給多個）。
2. 退出 1 → 先修 lint 與白名單路徑問題，再重跑。修完才繼續。純格式問題（ID 順序、⚠ 標記與層級不符、欄數、日期格式）可自行修；涉及內容的問題（缺必填欄、缺同義表達、缺重審條件、白名單路徑要換哪個檔）必須先問使用者，不猜。
3. 退出 2 → 進判定。**腳本輸出的「提示」欄只是排序，不是結論。**
   - 提示「疑似」：全部必判。
   - 提示「否定」「引用」：該項層級 ≥ 1 時全部必判；層級 0 時抽看，使用者要求就全判。
4. 每一筆判定的第一步是 **Read 該 R 的詳情檔**，然後照下面固定格式把輸入攤開再回答。

### 判定輸入（固定格式）

    R-ID：R-NNNN
    檔案:行：<相對路徑>:<行號>
    命中詞：<term>
    原句：<該行原文>
    前後 3 行：
      -3 <行>
      -2 <行>
      -1 <行>
      +1 <行>
      +2 <行>
      +3 <行>
    命題：<詳情檔的命題全文>
    範圍：<詳情檔的範圍全文>

判定問題固定一句：「這段是否把該命題當成現況、建議或主軸，且落在範圍內？」

### 判定輸出（三值）

- **復活**：是。列「復活：R-NNNN，檔案:行，原句，建議改法」，等使用者決定改不改。使用者確認後：Edit 索引該行「復活」欄 +1、「最近復活」欄填今天、詳情沿革追加 `- YYYY-MM-DD 復活於 檔案:行`。
- **乾淨**：有碰到這個題目，但沒有把命題當現況／建議／主軸（例如比較、歷史敘述、明確排除）。詳情沿革追加 `- YYYY-MM-DD 乾淨命中 檔案:行`。這條是降層的依據，一定要寫。
- **誤報**：根本不是在講這個命題（同名不同事、字串巧合）。不寫沿革；建議使用者是否把該詞從同義表達移除。

### 升降層提議

lint 出現「提醒：… 提議升 N」時照階梯提議，等使用者確認才改：

- 復活累計 ≥ 1 且層級 0 → 提議升 1：索引該行 ID 前加 `⚠ `，命題改寫成含範圍的完整句，詳情同義表達全部併進關鍵字欄，層級欄改 1。
- 復活累計 ≥ 2 且層級 < 2 → 提議升 2：把該條移進索引「## 0. 硬禁區」段，用 `### ⚠ R-NNNN 短標` 開頭，底下把命題、範圍、重審條件全文寫出；B 段該行層級欄改 2、保留 ⚠。硬禁區滿 5 條時先提議把最舊的降層。
- 降層（兩條件都要）：最近復活距今 ≥ 30 天，且該項詳情沿革中「乾淨命中」累計 ≥ 3 次。提議降一層，改層級欄與對應格式，復活累計數不清零。

5. 收工與交件前必跑。

## migrate（一次性搬舊裁決）

1. 使用者指定來源檔（例：v2 裁決紀錄末尾的勿復活清單、CLAUDE.md 的鐵條段、「已否決不再提」段）。
2. **先做「來源段落 → R-ID」對照表**：把每個來源的每一段列成一列，欄位為「來源檔:段落」「預定 R-ID 或去向」。去向只有三種：進帳本、進「已淘汰檔」子表、使用者判定丟棄。
3. 逐條抽成候選，每條照 add 第 2 步起草，**一次只給使用者看一條**，使用者回「好／跳過／改成…」。
4. 全部走完跑 `--lint`，退出 0。
5. 對照表逐列確認都有去向，沒有空白才可以動來源檔。
6. 回報：新增幾條、跳過幾條、丟棄幾條、來源檔哪些段落可刪（由使用者決定刪不刪，刪前備份）。

## 禁止

- 不自行蓋章、不自行改狀態、不猜使用者的意思補欄位。
- 帳本流程（add／check／migrate）中不寫入白名單與帳本以外的檔案。
- 不用 Bash heredoc 寫中文檔（用 Write／Edit 工具）。
- 不把任何立場句寫進 CLAUDE.md。
