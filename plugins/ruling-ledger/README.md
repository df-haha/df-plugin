# ruling-ledger 裁決帳本

每個 repo 一本帳本，記使用者對立場的裁決（採用／打掉／待裁）。索引永遠載入，詳情按關鍵字載入，避免被打掉的概念在下個 session 復活。

Claude 只提議，寫入帳本前一律等使用者明確同意。立場句不寫進 CLAUDE.md，CLAUDE.md 只留三行路由，指向索引。

## 安裝

    claude plugin marketplace add df-haha/df-plugin
    claude plugin install ruling-ledger@df-haha-plugins

安裝後可打 `/ledger`，也可用自然語言觸發，例如「記為打掉」「這條翻案」「查復活」「帳本」。

## 四個子指令

`/ledger init`
建立帳本：索引 `docs/裁決帳本.md`、詳情目錄 `docs/裁決/`，並在 CLAUDE.md 插入三行路由（先跑 `--dry-run` 給使用者看，使用者同意才正式寫）。首次建好時 A 段白名單是空的，需要使用者指名「現在算數的檔案」。

`/ledger add`
新增一條裁決，或幫既有裁決改狀態。Claude 先起草（ID、狀態、命題、範圍、理由、同義表達、重審條件、出處），整段貼給使用者確認，使用者說好才寫入索引與詳情檔。

`/ledger check`
跑 lint、白名單路徑檢查、復活掃描三項。掃描範圍預設是白名單檔加 CLAUDE.md，可用 `--scan <路徑>` 加掃草稿目錄。有命中時，每一筆都要對照原文與詳情檔判定，不能只看提示欄。

`/ledger migrate`
一次性把舊裁決紀錄（例如舊版 CLAUDE.md 的鐵條段、勿復活清單）搬進帳本。先列「來源段落 → R-ID」對照表，逐條給使用者確認，全部搬完再跑一次 `--lint` 確認乾淨。

## 帳本結構

索引 `docs/裁決帳本.md` 分五段：

- **0 硬禁區**：層級最高的裁決，命題、範圍、重審條件全文寫在索引裡，不必開詳情檔就看得懂。上限五條，滿了先提議把最舊的降層。
- **A 白名單＋已淘汰檔**：A 段是「現在算數的檔案」清單，只有列在這裡的檔才當事實來源；子表「已淘汰檔」登記已知含舊口徑、不得再引用的檔。
- **B 有效裁決**：七欄表格 `| ID | 狀態 | 命題 | 關鍵字 | 層級 | 復活 | 最近復活 |`，是查詢與掃描的主表。
- **C 已歸檔**：不再管事的裁決搬到這裡，詳情檔保留不刪。
- **D 記錄規則**：給 Claude 看的操作規則，包含升降層條件與寫入流程。

每條裁決另有一份詳情檔 `docs/裁決/R-NNNN.md`，欄位含命題、範圍、理由、同義表達、重審條件、出處與沿革，是判斷時的最終依據，索引只負責路由。

## 三個退出碼

`ledger_check.py` 的退出碼：

- **0**：lint、白名單路徑、復活掃描全部通過，沒有命中。
- **1**：lint 或白名單路徑有硬錯（提醒類訊息不算），要先修好才能繼續。
- **2**：有命中，需要逐筆對照詳情檔判定；提示欄（疑似／否定／引用）只影響排序，不是判定結果。
