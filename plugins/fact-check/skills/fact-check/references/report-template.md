# 驗證報告模板

## 檔案命名

`[原檔名]_驗證報告_[日期].md`

## 報告結構 Schema

```yaml
sections:
  1_執行摘要:
    format: "30 秒速覽"
    content: [正確項目數/總數, 致命錯誤數, 嚴重錯誤數, 中度問題數, 缺來源數, 技術籠統數]
    結尾: "一句話建議"

  2_致命錯誤:
    icon: "🚨"
    per_item:
      - "📍 位置：第X章「章節名」 > 第Y段"
      - "📝 原文引用：> 「...原文 20 字前後文...」"
      - "❌ 問題：編號列出所有問題"
      - "✅ 正確資訊：查證後的正確內容"
      - "📚 證據來源：3+ 來源，含⭐可信度評級和 URL"
      - "💡 建議修正：可直接替換的修正文字"

  3_嚴重錯誤:
    icon: "⚠️"
    per_item: (同致命錯誤格式)

  4_中度問題:
    icon: "📊"
    per_item: (同上，來源可減至 2 個)

  5_輕微問題:
    icon: "💡"
    per_item: [位置, 原文, 問題, 建議]

  6_正確但缺來源:
    icon: "✅"
    per_item:
      - "📍 位置標記"
      - "📝 原文引用"
      - "✅ 驗證結果：正確"
      - "📚 補充來源：3+ 來源（供作者添加）"

  7_技術查核結果:
    icon: "⚙️"
    format: "表格"
    columns: [原文描述, 問題類型, 建議修正]
    統計: [籠統描述數, 版本過時數, 技術錯誤數]

  8_可信度評分矩陣:
    format: "表格"
    dimensions: [事實準確性, 時效性, 來源完整性, 數據準確性, 技術準確性, 來源可信度]
    per_dimension: [評分百分比, 說明]
    底部: "整體評分 = 正確項目數 / 總項目數 × 100%"

  9_改善建議:
    format: "按位置排序的 checklist"
    levels:
      P0: "立即修正（致命錯誤）"
      P1: "強烈建議（嚴重錯誤）"
      P2: "建議修正（缺來源 + 中度問題）"
      P3: "優化（技術描述具體化）"
      P4: "錦上添花（格式、措詞）"

  10_來源完整列表:
    format: "按可信度分級"
    groups:
      - "⭐⭐⭐⭐⭐ 官方文件/學術期刊"
      - "⭐⭐⭐⭐ 權威媒體/產業報告"
      - "⭐⭐⭐ 一般媒體/技術社群"

  11_查證統計:
    content: [驗證時間, 並行agents數, WebSearch調用次數, 平均來源數/項, 查證成功率]
```

## 來源可信度標準

| 等級 | 來源類型 |
|------|---------|
| ⭐⭐⭐⭐⭐ | 官方文件、學術期刊、政府報告、官方 GitHub |
| ⭐⭐⭐⭐ | 權威媒體、上市公司財報、技術論文 |
| ⭐⭐⭐ | 一般新聞媒體、產業報告、技術部落格 |
| ⭐⭐ | 部落格、論壇（需交叉驗證） |
| ⭐ | 未知來源、社群媒體 |
| ❌ | 付費內容、公關稿（必須標註） |

## 錯誤嚴重性分級

| 等級 | 標準 |
|------|------|
| 🚨 致命 | 公司已停業仍描述為營運、完全無法查證的關鍵資訊、數據錯誤 >50%、根本性分類錯誤 |
| ⚠️ 嚴重 | 公司已被收購未更新、業務範圍錯誤、資料嚴重過時 >12 月、關鍵數據缺來源 |
| 📊 中度 | 資料過時 6-12 月、描述不完整、單一來源、模糊用語、術語不當 |
| 💡 輕微 | 拼寫錯誤不影響辨識、細節不精確、格式問題 |
