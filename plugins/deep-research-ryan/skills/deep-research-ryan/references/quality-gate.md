# Quality Gate 自檢規範

> **執行者**：Quality Gate Subagent（獨立 context）
> **輸入**：最終報告 + 此規範檔
> **輸出**：`qg-result.md`（精簡結論，供主對話讀取）

---

## §0 Canonical Constants（SSOT，單一常數來源）

> 本節為所有閘門常數的唯一權威。其他檔案（agent-config.md、synthesis-pipeline.workflow.js）與本節矛盾時一律以本節為準。

### Citation Verify 三指標（由 counts 機械計算）

- `retrievability = (matched + mismatched) / totalUrls`
- `support_rate = matched / (matched + mismatched)`（分母 0 時視為 0）
- `strict_support_coverage = matched / totalUrls`
- `unreachable_rate = unreachable / totalUrls`
- status 判定（機械）：
  - FAIL：`support_rate < 0.85` 或 `unreachable_rate > 0.25`
  - PASS_WITH_WARNINGS：非 FAIL 且（`support_rate < 0.95` 或 `unreachable_rate > 0.10`）
  - PASS：其餘
- 每筆 unreachable 必附：使用工具、HTTP/錯誤碼、重試次數、替代來源搜索結果；關鍵主張若僅剩 unreachable 證據 → 該資料點標 ⬜ UNVERIFIED
- 最多 2 輪；第 2 輪仍 FAIL 或 verifier agent 失敗 → `citationBlocked = true` → finalStatus 強制 NEED_MANUAL_REVIEW

### Quality Gate 三閘門（depth = quick|standard|deep；type = 研究類型）

**閘門 A（資料點信心分佈）**：
- deep：🟢 ≥60% 且 🟢+🟡 ≥85%
- standard：🟢 ≥50% 且 🟢+🟡 ≥80%
- quick：🟢 ≥40% 且 🟢+🟡 ≥75%

**閘門 B（加權聚合）**：門檻 = max(depth 門檻, type 門檻)
- depth 門檻：deep 0.80 / standard 0.70 / quick 0.60
- type 門檻：company（含投資決策維度）與商業決策類 0.80；person/region/social 0.60；其他 0.70

**閘門 C（LLM-as-judge rubric_avg）**：
- deep ≥0.75 / standard ≥0.65 / quick ≥0.55

**判定**：
- 任一閘門 fail → FAIL
- 全 pass + 任何 warning → PASS_WITH_WARNINGS
- 全 pass + 無 warning → PASS

**QG 輪數與修補**：
- QG 最多 2 輪
- QG repair 每輪最多 3 個 fixable warning，依序執行（sequential，禁止並行）

**資料點覆蓋率**：
- 資料點 4 項標註（信心符號 + L 級 + URL + 日期）覆蓋率 ≥90%，未達 → PASS_WITH_WARNINGS

### data_self_consistency canonical checklist（7 項；文件與 workflow prompt 共用）

1. 跨章節同指標數字一致
2. 單位換算（萬/億、million/billion）
3. 幣別與匯率日期、名目/實質金額
4. 資料期間 vs 發布日期錯位（過去數據描述為現況）
5. 地域範圍混淆（全球/區域/國家）
6. 百分比 vs 百分點 vs 絕對數
7. 加總、成長率、衍生計算正確性

每筆 warning 附：原始值、正規化值、兩個出現位置、採用的換算假設。

## 自檢流程（7 層）

### 1. 數據自洽檢查

依 §0 canonical checklist 7 項逐一掃描報告中的所有數字：

1. 跨章節同指標數字一致（例：執行摘要的營收 vs 財務章節的營收）
2. 單位換算（萬/億、million/billion）
3. 幣別與匯率日期、名目/實質金額
4. 資料期間 vs 發布日期錯位（過去數據描述為現況）
5. 地域範圍混淆（全球/區域/國家）
6. 百分比 vs 百分點 vs 絕對數
7. 加總、成長率、衍生計算正確性

每筆 warning 附：原始值、正規化值、兩個出現位置、採用的換算假設。
發現不一致 → 記錄於輸出，標明位置和建議修正。

### 2. 維度覆蓋檢查

對照 `references/dimensions.md` 的必要維度清單，檢查：
- 每個必要維度是否有對應章節且有實質內容
- 是否有空白章節（只有標題沒有內容）
- 缺失維度標記原因：
  - ⬜ 無資料（搜索後未找到）
  - N/A 不適用（該維度對此研究類型不相關）
  - 🔴 遺漏（應有但未覆蓋）

### 3. 信心評級門檻

統計報告中的信心評級分佈，使用**動態門檻**（依研究類型調整）+ **加權聚合 sanity check**。

### 動態信心門檻

| 研究類型 | 🟢+🟡 最低門檻 | 說明 |
|---------|--------------|------|
| 商業模式可行性 / 公司研究（投資決策用）| ≥ **80%** | 決策風險高，需更嚴格驗證 |
| 產品研究 / 技術研究 / 產業研究 | ≥ **70%** | 標準門檻 |
| 人物研究 / 地區研究 / 社會議題 | ≥ **60%** | 資料本身較主觀，門檻適度放寬 |

### 分母定義

**舊版漏洞**：「🟢+🟡 ≥ 80%」未定義分母（所有數據點/所有維度/核心結論/加權後維度分數？），同樣 100 個資料點分母不同信心率差 30%。

**新規則**：

1. **分母 = 報告中所有附信心評級的資料點數**（含 🟢🟡⚠️⬜❗ 五種；不含未標評級的描述性文字）
2. **⬜ 無資料計入分母**（這是「找了沒找到」的真實狀態，計算佔比時必須納入；否則 ⬜ 多就分母小，假性達標）
3. **❗ 矛盾計入分母**（仲裁失敗的也是研究品質問題）
4. **每個資料點只算一次**（多章節重複引用同一資料點，第一次出現位置為準）

### 分母嚴格採用「資料點級」（強制）

舊版雖然定義分母 =「報告中所有附評級資料點數」，但實作上 subagent 可能採章節級星級評級，導致分母小（實測案例：曾發生 50/64 = 78.1% 差 1.9% 險些達標的情況）。

**強制規則**：QG 第 1 步必須統計報告中「斷言/數字/結論」總數 vs 「附完整 4 項標註（🟢🟡⚠️⬜❗ + L 級 + URL + 日期）」數。
- 若標註率 <90% → QG 第 1 層直接 PASS_WITH_WARNINGS（資料點級評級覆蓋不足）
- 若標註率 ≥90% → 進閘門 A 計算
- 章節級星級評分不參與計算（強制取代為資料點級）

### 判定規則

- 🟢 已驗證 + 🟡 單一來源 ≥ **門檻值** → ✅ 通過分佈門檻
- ⚠️ 推估值 + ⬜ 無資料 + ❗ 爭議未解 > **(100% - 門檻值)** → ⚠️ 警告
  - 列出所有 ⬜ 無資料項目，建議補查方向
  - 補查由主對話決定是否執行（QG subagent 本身不發起補查）

### 加權聚合 sanity check

**舊版漏洞**：QG 只統計分佈百分比，但 `verification.md` §9 加權聚合公式（核心維度 ×3、重要 ×2、輔助 ×1，🟢=1.0 🟡=0.7 ⚠️=0.4 ⬜=0 ❗=0）從未被引用——兩套並行的信心系統互不通氣。

**新規則（雙閘門）**：

QG 同時跑兩個信心算法，兩個都過才算 PASS：

- **閘門 A（分佈門檻）**：上方「🟢+🟡 / 全部 ≥ 門檻值」
- **閘門 B（加權聚合）**：用 `verification.md` §9 公式算「整體信心指數」（0.0-1.0）：

  ```
  整體信心指數 = Σ(維度權重 × 維度信心分數) / Σ(維度權重)
  
  其中：
  - 維度權重：核心維度（dimensions.md 標 P1）= 3、重要維度（P2）= 2、輔助維度（P3）= 1
  - 維度信心分數 = Σ(該維度資料點的 評級分數) / 該維度資料點數
  - 評級分數（SSOT：§0 評級分數表）：🟢=1.0、🟡=0.7、🔴=0.5、⚠️=0.3、❗=0.2、⬜=0
  ```

### 三閘門（SSOT：§0 Canonical Constants）

> 常數以 §0 為準。本節為判定矩陣說明。

**三閘門定義**：
- 閘門 A（分佈門檻）：🟢+🟡 / 全部資料點 ≥ 動態門檻（依 §0 depth 對照表）
- 閘門 B（加權聚合）：依 verification.md §9 公式算 0-1 分，≥ max(depth 門檻, type 門檻)（見 §0）
- 閘門 C（LLM-as-judge）：依本檔第 7 層的 overall_rubric_score，≥ §0 depth 門檻

**判定**（簡化規則，取代舊版判定矩陣）：
- 任一閘門 fail → FAIL
- 全 pass + 任何 warning → PASS_WITH_WARNINGS
- 全 pass + 無 warning → PASS

**閘門 C 阻擋事實錯誤**——這是純分佈閘門做不到的。

**Sanity check 範例**：

```
報告共 50 個附評級資料點：🟢 28、🟡 8、⚠️ 6、⬜ 5、❗ 3

閘門 A：🟢+🟡 = 36 / 50 = 72%（門檻 70%）→ ✅ 達標

閘門 B 加權聚合：
- 維度 1 (P1，6 個資料點)：4×1.0 + 2×0.7 = 5.4 / 6 = 0.90
- 維度 2 (P1，10 個資料點)：6×1.0 + 2×0.7 + 1×0.3 + 1×0 = 7.7 / 10 = 0.77
- 維度 3 (P2，8 個資料點)：5×1.0 + 1×0.7 + 1×0.3 + 1×0 = 6.0 / 8 = 0.75
- 維度 4 (P3，6 個資料點)：3×1.0 + 1×0.7 + 1×0.3 + 1×0 = 4.0 / 6 = 0.67
- ...

整體信心指數 = (3×0.90 + 3×0.77 + 2×0.75 + 1×0.67 + ...) / Σ權重 = 0.80

整體判定：✅ PASS（A 達標 + B 0.80 ≥ 0.7）
```

### 4. 行動手冊完整度檢查

確認報告包含以下必要組件：
- [ ] 供應商/方案優先度排序表
- [ ] 分階段實施路線圖（至少 Phase 1/2/3 或月度級別）
- [ ] 成本分項表（環節級別，非籠統描述）
- [ ] 下一步行動清單（具體可執行）
- [ ] Pre-mortem 失敗情境分析
- 缺失項目 → 記錄於輸出，標明「建議從 Phase 1/2 資料補充」

### 5. 時效性檢查
掃描報告中所有數據點的資料時間標記（見 `verification.md` §10）：

- 統計 🕐 即時 / 🕐 近期 / ⏰ 需注意 / ⚠️ 過時風險 的分佈
- **⏰ + ⚠️ 佔比 > 20%** → ⚠️ 警告，列出過時數據項目
- 核心結論所依賴的數據若標記 ⚠️ 過時風險 → 🔴 必要修正
- 無時間標記的數據點 → 記錄為「時效不明」，建議補標

### 6. 邏輯一致性檢查
交叉檢查報告的批判性分析結果：

- **Steel-man 反論 vs 決策建議**：檢查結論韌性為「弱」的項目，是否在決策建議中已加入對應警告或條件限制
- **假設審計 vs 結論**：檢查穩固度為 🔴 低的假設，其對應結論是否標有足夠的不確定性說明
- **Devil's Advocate vs 情境展望**：反論提出的風險因素是否已納入悲觀情境分析
- 發現邏輯不一致 → 記錄具體位置，建議修正方向

### 7. LLM-as-judge 5 項 Rubric 檢查
業界 SOTA 標配（FactScore/RAGAS/ALCE 對標）。讀 ${RUN_DIR}/citation-verify_{YYYYMMDD}.md 的 rubric 區段（由 §14 Citation Verifier 產出），執行：

- **factual_accuracy** ≥ 0.85 才及格
- **citation_accuracy** ≥ 0.90 才及格
- **completeness** ≥ 0.80 才及格
- **source_quality** ≥ 0.70 才及格
- **tool_efficiency** 不及格門檻（純資訊性，不阻塞）

整體 overall_rubric_score（5 項平均）≥ 0.80 才算第 7 層通過。

判定：
- 7/7 項都達標 → 第 7 層 PASS
- 6/7 項達標（含 tool_efficiency 不及格）→ 第 7 層 PASS
- 5/7 或更少達標 → 第 7 層 PASS_WITH_WARNINGS（列出未達標項）
- 任一核心項（factual/citation）<0.5 → 第 7 層 FAIL，觸發補查

## PASS_WITH_WARNINGS 補查閉環
**舊版漏洞**：補查由主對話決定，主對話為了快結束會全選「標記後直接 DONE」，警告永遠不被處理；補查跑完後也沒重跑 QG 驗證補查成效，可能補了沒效或補出新衝突也照樣 DONE。

**新規則（強制閉環，最多 2 輪 QG）**：

### 觸發條件
QG 結果為 `PASS_WITH_WARNINGS` 時，主對話**必須**判斷以下兩類：

1. **核心結論依賴的 ⬜ 或 ⚠️ 資料點**（如：投資決策結論依賴的營收數字標 ⚠️ 過時）
   → **強制補查 ≥1 輪**，禁止「標記後直接 DONE」
2. **非核心 ⬜ / ⚠️**（如：背景脈絡的某個輔助數據缺）
   → **可標記**寫入 README 的「研究侷限性」章節後 DONE，無需補查

### 補查執行
- 派 1-2 個補查 subagent（用本 file §5 模板，限定為「補某個指定資料點」窄任務）
- 補查結果寫入 `phase2/補查_{資料點名}_{YYYYMMDD}.md`
- 補查 subagent 落地後**必須回報主對話**「補了 N 個資料點、新信心評級」

### 重跑 QG（強制）
- 補查完成後，**主對話必須重新派 QG subagent 跑完整 7 層**（不能只 patch）
- 重跑 QG 讀新增的補查檔案 + 原報告

### 終止條件
- 重跑後 PASS → README + DONE
- 重跑後仍 PASS_WITH_WARNINGS → **檢查是否同一警告**：
  - 同一警告 = 補查無效 → 標 FAIL，告知用戶手動審視
  - 新警告（補查引入新問題）→ 第 2 輪補查 + 第 2 次重跑 QG
- **總共最多 2 次重跑 QG**（避免無限迴圈）
- 2 輪後仍 FAIL → 寫入 README「QG 未達標項目」並告知用戶，**禁止**靜默通過

### Citation Verification 與 QG 的關係- 流程順序：`Synthesis → Citation Verifier → QG`
- Citation Verifier 的 `citation-verify.md` 是 QG 第 6 層「邏輯一致性」的必讀輸入
- 若 Citation Verifier 自身 FAIL（>15% no_match）→ 不進 QG，直接派補查改報告引用、重跑 Synthesis 一輪
- 若 Citation Verifier PASS / PASS_WITH_WARNINGS → 進 QG，QG 把 citation 結果納入第 6 層判定
