## 1. PESTEL 分析（宏觀環境）

適用：商業模式可行性、產業研究、地區研究

| 維度 | 英文 | 關鍵問題 |
|------|------|---------|
| 政治 | Political | 政府政策方向？補貼或限制？地緣政治風險？ |
| 經濟 | Economic | GDP 走勢、通脹、利率、消費力、匯率？ |
| 社會 | Social | 人口結構、消費習慣、文化態度、世代差異？ |
| 技術 | Technological | 關鍵技術成熟度、數字化程度、研發投入？ |
| 環境 | Environmental | 碳政策、ESG 要求、資源稀缺性？ |
| 法律 | Legal | 行業法規、准入限制、知識產權、勞動法？ |

**輸出格式**：
```
PESTEL 評估：
P 政治：[正面/中性/負面] — [說明]
E 經濟：[正面/中性/負面] — [說明]
S 社會：[正面/中性/負面] — [說明]
T 技術：[正面/中性/負面] — [說明]
E 環境：[正面/中性/負面] — [說明]
L 法律：[正面/中性/負面] — [說明]
整體評估：[有利/中性/不利]
```

## 2. Moat 護城河分析

適用：公司研究、商業模式可行性、競爭格局分析

護城河來源（4 種，可疊加）：

| 護城河類型 | 典型表現 | 強度判斷標準 |
|----------|---------|------------|
| **網絡效應** | 用戶越多越有價值（社交/平台/數據飛輪）| 交叉網絡效應 > 單邊網絡效應 |
| **切換成本** | 用戶轉換到競品的代價高（數據/習慣/整合）| 成本越高越強，量化估算遷移代價 |
| **無形資產** | 品牌、專利、特許經營、監管資質 | 專利到期時間？品牌溢價幅度？ |
| **成本優勢** | 結構性成本比競品低（規模/流程/技術）| 是否可持續？競品能否複製？ |

**輸出格式**：
```
護城河評估：
- 網絡效應：[強/中/弱/無] — [說明]
- 切換成本：[強/中/弱/無] — [說明]
- 無形資產：[強/中/弱/無] — [說明]
- 成本優勢：[強/中/弱/無] — [說明]
綜合 Moat 強度：[強/中/弱]
主要威脅：[最可能打破護城河的因素]
```

## 3. Unit Economics 單位經濟

適用：商業模式可行性、公司財務分析、產品研究

核心指標定義：

| 指標 | 定義 | 健康基準 |
|------|------|---------|
| **CAC** | 客戶獲取成本（銷售+行銷費用/新客戶數）| 因行業而異 |
| **LTV** | 客戶終身價值（ARPU × 平均留存月數 × 毛利率）| 通常 LTV ≥ 3× CAC |
| **LTV/CAC** | 投資回報倍數 | < 1 燒錢，1-3 可接受，> 3 健康 |
| **回本期** | CAC / 月均毛利貢獻 | B2B 通常 < 18 個月 |
| **毛利率** | (收入 - 直接成本) / 收入 | SaaS > 70%，電商 > 40% |
| **NDR** | 淨收入留存率（現有客戶的擴張/收縮）| > 110% = 負流失 |
| **Churn Rate** | 流失率（月/年）| SaaS 月流失 < 3% 可接受 |

**輸出格式**：
```
Unit Economics 評估：
CAC：$[數值]（🟢已驗證/🟡推估）
LTV：$[數值]（🟢已驗證/🟡推估）
LTV/CAC：[倍數]
回本期：[月數]
毛利率：[%]
結論：[可持續/邊緣/不可持續]，主要槓桿：[降 CAC/提 LTV/其他]
```

## 4. 維他命 vs 止痛藥（需求強度）

適用：產品研究、商業模式可行性

| 類型 | 特徵 | 商業影響 |
|------|------|---------|
| **止痛藥** | 解決迫切問題，用戶「必須有」，願付高價 | 銷售難度低，定價能力強，擴張快 |
| **維他命** | 提供增益，用戶「nice to have」，容易推遲購買 | 銷售難度高，流失率高，定價受限 |
| **混合型** | 切入點是維他命，但具備轉化為止痛藥的路徑 | 需找到「關鍵使用場景」觸發依賴 |

**判斷問題**：
1. 目標客戶在沒有這個產品時是如何解決問題的？
2. 他們現在為同類解決方案付多少錢/花多少時間？
3. 如果明天這個產品消失，他們會怎樣？

## 5. Why Now? 時機分析

適用：商業模式可行性、技術研究、新創公司分析

**觸發因素清單**：

| 類別 | 典型觸發因素 |
|------|------------|
| 技術成熟 | 某關鍵技術從實驗室走向商業化（如 GPU 成本下降推動 AI）|
| 法規變化 | 新法規開放市場或創造合規需求 |
| 行為轉變 | 疫情/社會事件改變消費者習慣，形成新基線 |
| 成本拐點 | 關鍵硬件/軟件成本跌破某個臨界點 |
| 基礎設施就緒 | 5G、雲計算、支付基礎設施到位 |
| 市場教育完成 | 早期玩家已完成市場教育，現在是收割時機 |

**輸出格式**：
```
Why Now? 評估：
觸發因素：[列出 2-3 個最關鍵的時機因素]
時機窗口：[預計多久窗口保持開放]
先行者優勢：[是否存在？強弱程度？]
```

## 6. Pre-mortem 預死亡分析

適用：所有研究類型的風險評估部分。另見 §10 Steel-man 反論（兩者差異見下方對照表）。

### Pre-mortem vs Steel-man 差異定位

| 維度 | Pre-mortem（§6） | Steel-man（§10） |
|------|-----------------|-----------------|
| 時間軸 | 假設**未來**已失敗，倒推失敗原因 | 檢驗**當前**論證的最強反面版本 |
| 輸入 | 研究結論 + 外部失敗案例 | 3 個核心結論 + 反面證據搜索 |
| 輸出 | 失敗情境排序 + 預警信號 + 緩解策略 | 結論韌性評級（強/中/弱）+ 修正後結論 |
| 禁止重複 | 不做結論反駁（那是 Steel-man 的事） | 不做時間線推演或失敗案例排序（那是 Pre-mortem 的事） |

**操作方法**：
假設這個公司/產品/商業模式「5 年後已經失敗」，回頭分析最可能的失敗原因。

**常見失敗模式**：

| 失敗模式 | 典型表現 |
|---------|---------|
| 市場規模不足 | TAM 比預期小，無法支撐規模化 |
| 技術路線選錯 | 選擇了邊緣化技術路線，被主流替代 |
| 燒錢無法盈利 | Unit Economics 始終未達健康 |
| 競品降維打擊 | 大廠將此功能內建化（bundling 打法）|
| 監管收緊 | 依賴的灰色地帶被法規封堵 |
| 核心人才流失 | 創辦人/關鍵技術人離開後陷入停滯 |
| 時機太早 | 市場未成熟，後來者享受了鋪路成果 |
| 執行失敗 | 策略正確但組織能力、資金不足 |

**輸出格式**：
```
Pre-mortem 分析：
最可能的失敗場景（前 3 名）：
1. [失敗模式]：[具體描述] — 類似案例：[案例名稱]
2. [失敗模式]：[具體描述] — 類似案例：[案例名稱]
3. [失敗模式]：[具體描述] — 類似案例：[案例名稱]
緩解策略：[針對最高風險的應對措施]
```

## 8. 信心評級系統（報告全文使用）

所有主要數據點必須附信心評級：

| 符號 | 含義 | 使用條件 |
|------|------|---------|
| 🟢 已驗證 | 2+ 獨立來源一致 | 多工具交叉驗證通過 |
| 🟡 單一來源 | 只有一個來源，來源可信 | 官方文件/主流媒體 |
| 🔴 已裁定衝突 | 有衝突但已解決 | Resolution Search 裁定後 |
| ⚠️ 推估值 | 無直接資料，由競品/行業均值推估 | 必須標明推估基礎 |
| ⬜ 無資料 | 搜索後仍無法找到 | 說明可能原因 |
| ❗ 爭議未解 | 有衝突但無法裁定 | 保留各方說法 |

### v2 強制：資料點級評級（取代章節級⭐⭐⭐⭐⭐）

舊版漏洞：報告採章節級星級信心評級不利機械化計分（實測案例：曾發生閘門 A 78.1% 差 1.9% 的情況，主因正是分母小、章節級無法精確計算分佈）。

**新強制規則**：
1. 每個「資料點」必須附 4 項：
   - 信心符號（🟢 ≥3 獨立來源 / 🟡 1-2 來源 / ⚠️ 推估 / ⬜ 無資料 / ❗ 矛盾）
   - L1-L6 來源等級（見 verification.md §6 對照表）
   - URL 或一手出處
   - 採集日期
2. 「資料點」定義：報告中任何被引用或斷言的具體事實/數字/結論，包括：
   - 任何數字（營收/估值/市佔率/百分比）
   - 任何專有名詞首次出現的描述
   - 任何因果或關聯陳述
   - 排除：常識性陳述、過渡語
3. 標示格式範例：
   - `Q1 2026 收入 $1.63B（+85% YoY） 🟢 L1 sec.gov 2026-04-15`
   - `Bootcamp 轉換率 75% ⚠️ L4 [公司] IR 引述 [季度 call] [日期]（公司未公佈精確值）`
4. **章節級 ⭐⭐⭐⭐⭐ 評級可保留**作為「整章敘事品質印象」，但**不參與 QG 雙閘門計算**（QG 只看資料點級）。

執行：subagent 寫報告時、每段第一句話之外的任何具體斷言必須附此 4 項。漏附超過 10% 觸發 QG 第 1 層 PASS_WITH_WARNINGS。

## 9. 情境分析框架（Scenario Analysis）

適用：所有研究類型的「情境展望」章節（見 `output-template.md`）

**核心思路**：不給單一預測，而是呈現多種可能的發展路徑，讓用戶根據後續觀察自行判斷走向。

### 情境構建方法

1. **識別關鍵不確定因素**：從研究中找出 2-3 個影響最大且不確定性最高的因素
2. **交叉組合生成情境**：不同因素的正面/負面組合產生不同情境
3. **為每個情境設定觸發條件和驗證指標**

### 三情境模型

| 情境 | 定義 | 機率表述 |
|------|------|---------|
| 樂觀情境 | 多數不確定因素向好發展 | 高/中/低 |
| 基準情境 | 最可能的發展路徑（現狀延續 + 合理趨勢）| 通常為「高」 |
| 悲觀情境 | 主要風險因素兌現 | 高/中/低 |

**注意**：機率使用「高/中/低」三級，不使用精確百分比（LLM 無法做真正的概率計算）。

### 輸出格式

```
情境展望：

樂觀情境（發生機率：[高/中/低]）
- 觸發條件：[具體可觀測的條件]
- 預期結果：[對研究主題的影響]
- 驗證指標：[未來 3-6 個月觀察什麼]

基準情境（發生機率：[高/中/低]）
- 觸發條件：[具體可觀測的條件]
- 預期結果：[對研究主題的影響]
- 驗證指標：[未來 3-6 個月觀察什麼]

悲觀情境（發生機率：[高/中/低]）
- 觸發條件：[具體可觀測的風險因素]
- 預期結果：[對研究主題的影響]
- 預警信號：[出現什麼跡象需立即關注]

關鍵分岔點：[什麼事件/指標會決定走向哪個情境]
建議觀察頻率：[每月/每季/每半年回顧一次]
```

### 二階效應分析
每個情境不只分析直接影響，還需推演利害關係人的反應和後續連鎖效應。

```
二階效應分析：

| 情境 | 一階效應（直接影響）| 利害關係人反應 | 二階效應（連鎖影響）|
|------|------------------|--------------|-------------------|
| 樂觀 | [直接結果] | [競爭者/客戶/監管者會如何反應] | [反應導致的進一步影響] |
| 基準 | [直接結果] | [反應] | [連鎖影響] |
| 悲觀 | [直接結果] | [反應] | [連鎖影響] |

關鍵二階效應提醒：
- [效應1]：[說明為什麼這個連鎖反應值得注意]
- [效應2]：[說明]
```

## 10. Steel-man 反論框架

適用：所有研究類型的批判性分析。由 S-1 Subagent 執行。另見 §6 Pre-mortem（兩者差異見 §6 對照表）。

**核心原則**：對研究的每個核心結論，主動構建**最強的反面論述**，然後搜索支持該反論的證據。不是為了推翻結論，而是為了讓結論更穩固——能承受最強反駁的結論才是真正可靠的。

### 操作方法

對報告的 3 個最重要結論，各執行一次 Steel-man：

1. **提取核心結論**：從分析中識別出最重要的 3 個結論
2. **構建最強反論**：站在反對者的立場，用最合理的邏輯和最強的論據反駁該結論
3. **搜索反論證據**：搜索支持反論的真實數據和案例
4. **評估結論韌性**：核心結論能否在反論面前站住腳？

### 輸出格式

```
Steel-man 反論分析：

### 結論 1：[核心結論陳述]
**最強反論**：[站在反對者立場的最合理論述]
**反論依據**：
- [數據/案例/邏輯 1]（來源：[URL]）
- [數據/案例/邏輯 2]（來源：[URL]）
**結論韌性評估**：[強/中/弱]
- 強：反論有理但證據不足以推翻核心結論
- 中：反論提出了有效質疑，核心結論需附加條件
- 弱：反論有力，核心結論可能需要修正
**修正後結論**（如需）：[修正後的更謹慎表述]

### 結論 2：[核心結論陳述]
...（同上格式）

### 結論 3：[核心結論陳述]
...（同上格式）
```

## 11. 假設審計框架
適用：所有研究類型。在 Synthesis 階段、決策建議之前執行。

**核心原則**：每個結論都建立在隱含的前提假設之上。明確列出這些假設，評估其成立的機率，標記哪些結論因假設脆弱而需要額外謹慎。

### 操作方法

1. 對每個核心結論，逆向推導其隱含的前提假設
2. 對每個假設評估其成立的穩固程度
3. 標記高風險假設（若不成立會顯著影響結論）

### 輸出格式

```
假設審計：

| 核心結論 | 隱含假設 | 假設穩固度 | 若假設不成立 |
|---------|---------|-----------|------------|
| [結論1] | 假設A：[描述] | 🟢 高（有直接證據支持） | [影響說明] |
| [結論1] | 假設B：[描述] | 🟡 中（合理推論但無直接證據） | [影響說明] |
| [結論2] | 假設C：[描述] | 🔴 低（缺乏證據，依賴行業常識） | [影響說明] |

高風險假設提醒：
- 假設 [B/C]：若不成立，[結論X] 需重新評估。建議 [如何驗證]。
```

## 12. 投資決策框架組（v2 新增）

適用：公司研究（投資決策評估維度）、商業模式可行性。**只整理既有第三方分析，不自行從零建模**（避免 LLM 給出假精準的 DCF 數字）。

### 12.1 DCF 三情境表（第三方整理）

**用途**：對比賣方/買方分析師對同一標的的 DCF 估值差異，呈現分歧區間而非單一目標價。

**操作方法**：
1. 從 Seeking Alpha / Tikr / Simply Wall St / GuruFocus / SumZero 抓 ≥3 份分析師 DCF 報告（含 WACC、g、FCF 假設）
2. 把每份的「悲觀/基準/樂觀」三情境整理成下表
3. 標出**共識區間**（≥2/3 分析師同意的範圍）與**異常值**（最高/最低）
4. 不可自己加估值——只整理既有

**輸出格式**：
```
DCF 三情境（第三方整理，N 份來源）：

| 情境 | 隱含目標價 | 共識區間 | WACC 範圍 | 永續成長率 g | 主要假設差異 |
|------|-----------|---------|-----------|-------------|-----------|
| 悲觀 | $X-$Y | $A-$B (M/N 同意) | 8-12% | 1-2% | [描述] |
| 基準 | $X-$Y | $A-$B (M/N 同意) | 8-10% | 2-3% | [描述] |
| 樂觀 | $X-$Y | $A-$B (M/N 同意) | 7-9% | 3-4% | [描述] |
| 當前股價 | $Z | — | — | — | — |

| 異常值來源 | 目標價 | 為何偏離共識 |
|-----------|--------|-----------|
| [分析師A] | $W | [假設X 比共識高/低 Y%] |

來源列表：[3+ 份來源，含分析師姓名、發布日、評級]
信心評級：🟢/🟡/⚠️
```

### 12.2 可比公司倍數矩陣（Comparable Company Multiples）

**用途**：用同產業可比公司的 PE / EV/EBITDA / P/S / PEG / EV/Sales 倍數，框出目標公司的相對估值區間。

**操作方法**：
1. 列出 ≥5 家可比公司（同產業 + 規模相近 + 商業模式相似）
2. 抓每家當前的 5 個倍數（PE / EV/EBITDA / P/S / PEG / EV/Sales），來源用 Tikr / Stockanalysis / Yahoo Finance
3. 算中位數、四分位距，比對目標公司倍數位置
4. 標註「為何 premium / discount」的可能解釋

**輸出格式**：
```
可比公司倍數矩陣（N=5+，截至 [日期]）：

| 公司 | 市值 | PE (TTM) | EV/EBITDA | P/S | PEG | EV/Sales |
|------|------|----------|-----------|-----|-----|----------|
| [目標公司] | $X | A | B | C | D | E |
| [可比1] | $X | A' | B' | C' | D' | E' |
| ...
| **中位數** | — | M_PE | M_EV/EBITDA | M_P/S | M_PEG | M_EV/Sales |
| **四分位距** | — | [Q1-Q3] | [Q1-Q3] | [Q1-Q3] | [Q1-Q3] | [Q1-Q3] |

目標公司倍數相對位置：[Premium X% / Discount Y% / 中位數]
可能解釋：
- [假設 1：成長性高於同業 → premium 合理]
- [假設 2：利潤率低於同業 → discount 合理]
- [異常：[倍數] 偏離過大 → 需深究]

來源：[5+ 份]
信心評級：🟢/🟡
```

### 12.3 Counter-positioning（7 Powers 之一，Hamilton Helmer）

**用途**：判斷在位者是否因既有商業模式「無法模仿新進者」（不是不想，是不能）。比傳統 Moat 4 力（網絡/切換/無形/成本）更現代。

**操作方法**：
1. 識別新進者的關鍵商業模式特徵（如低價、訂閱制、開源）
2. 對在位者問三個問題：
   - **能複製嗎？** 技術上能不能做？
   - **複製代價是什麼？** 會傷害既有業務嗎？（食 cannibalization）
   - **為何不複製？** 既有業務太賺/估值太高/股東反對？
3. 若三個問題答「能 / 會傷既有 / 利益衝突」，則 counter-positioning 成立

**輸出格式**：
```
Counter-positioning 分析：

對象：[新進者 X] vs [在位者 Y]
新進者商業模式關鍵：[低價/訂閱/開源/...]

在位者反應評估：
| 問題 | 答案 | 證據 |
|------|------|------|
| 技術上能複製嗎？ | 能/不能 | [說明] |
| 複製代價（既有業務食 cannibal）| 高/中/低 | [%營收受影響] |
| 為何不複製（誘因衝突）| [描述] | [年報/法說會引文] |

Counter-positioning 評級：
- 🟢 強：三個問題答「能/高/有強烈不複製誘因」→ 新進者結構性領先
- 🟡 中：兩個問題符合 → 有時間窗口優勢
- ⚠️ 弱：只一個符合 → 普通競爭

歷史案例對照：[Netflix vs Blockbuster / Vanguard vs 主動基金 / AWS vs 傳統 IT]
信心評級：🟢/🟡/⚠️
```

### 12.4 ROIIC（Incremental ROIC，邊際資本回報率）

**用途**：判斷公司新增投入的資本能產生多少邊際回報——比 ROIC（累積平均）更能看出資本配置效率變化。Pershing Square 寫信給投資人時最常引用的單一指標。

**公式**：
```
ROIIC = (NOPAT_t - NOPAT_{t-1}) / (Invested Capital_{t-1} - Invested Capital_{t-2})
```

**操作方法**：
1. 從 10-K / 年報抓 ≥3 年的 NOPAT（稅後營業利潤）+ Invested Capital（含 PPE、營運資金、無形資產）
2. 計算逐年 ROIIC，看趨勢
3. 對標 WACC（資金成本）：ROIIC > WACC = 創造價值；< WACC = 毀滅價值

**輸出格式**：
```
ROIIC 趨勢（N 年）：

| 年度 | NOPAT 增量 | Invested Capital 增量 | ROIIC | WACC | 價值創造 |
|------|-----------|---------------------|-------|------|---------|
| 2023 | $X | $Y | A% | 8% | +/- |
| 2024 | $X | $Y | A% | 8% | +/- |
| 2025 | $X | $Y | A% | 8% | +/- |

趨勢判讀：
- 持續 > WACC → 資本配置健康
- 短期高但下滑 → 可能進入飽和
- 持續 < WACC → 資本錯配，管理層應停止再投資

歷史對照：[公司同期 ROIC 平均 vs 邊際 ROIIC]
信心評級：🟢（自家財報）
```

## 13. GTM 行銷框架組（v2 新增）

適用：產品研究（GTM 行銷策略維度）、商業模式可行性。

### 13.1 Bullseye Framework（獲客渠道優先級，Traction 一書）

**用途**：系統性對比 19 種獲客渠道，找出當前階段最高 ROI 的 3 個。出自 Gabriel Weinberg《Traction》（DuckDuckGo 創辦人）。

**19 種渠道清單**：
1. 病毒行銷 Viral Marketing
2. 公關 PR
3. 非傳統公關（如惡作劇/捐贈活動）
4. 搜尋引擎行銷 SEM
5. 社群與展示廣告
6. 線下廣告
7. SEO
8. 內容行銷
9. Email 行銷
10. 工程行銷（免費工具/小遊戲）
11. Targeting 部落格
12. BD 商務開發
13. 業務 Sales
14. 聯盟行銷 Affiliate
15. 既有平台（FB/Apple Store/Chrome Webstore）
16. 商展
17. 線下活動
18. 演講
19. 社群建構 Community Building

**操作方法**：
1. **Outer Ring**（外圈）：對 19 種渠道各想 1 個瘋狂的測試
2. **Middle Ring**（中圈）：選 3-5 個最有潛力的，做小規模測試（cost ≤ $500 / 時間 ≤ 1 週）
3. **Inner Ring**（內圈）：選 CAC 最低 + LTV 預期最高的 1 個 all-in
4. 每 3-6 個月重做一次（規模成長後最佳渠道會變）

**輸出格式**：
```
Bullseye 渠道分析（當前階段：種子/A 輪/B 輪/規模化）：

| 渠道 | 適合度 | 預估 CAC | 測試成本 | 推薦 Ring |
|------|--------|---------|---------|-----------|
| [渠道 1] | 高/中/低 | $X | $Y | Inner/Middle/Outer |
| ...

Inner Ring 建議：[渠道名] — 理由：[CAC 低 + 預期 LTV/CAC > 3]
Middle Ring 測試清單：[3-5 個]
Outer Ring 創意：[列 5 個跳脫常規的測試]

競品對標：[競品 A 主力渠道 = X，CAC ≈ $Y]
信心評級：🟢/🟡
```

### 13.2 STP（Segmentation / Targeting / Positioning，Philip Kotler）

**用途**：把市場切分 → 選目標客群 → 定位差異化敘事。產品研究的定位章節必用。

**操作方法**：

**Step 1 — Segmentation 切分市場**：
- 人口統計（年齡/性別/收入/教育）
- 地理（國家/城市/氣候）
- 心理（生活風格/價值觀/個性）
- 行為（使用頻率/品牌忠誠/購買時機）

**Step 2 — Targeting 選目標客群**：
評估每個 segment 的 5 項：
- 規模（≥多少人）
- 成長性
- 競爭強度
- 與自家能力匹配度
- 可觸達性

**Step 3 — Positioning 定位**：
April Dunford《Obviously Awesome》5 點定位框架：
1. **競品替代** Competitive Alternatives（用戶不選你會選什麼）
2. **獨特能力** Unique Attributes（你能做但別人不能）
3. **價值點** Value（這些能力帶來的好處）
4. **目標客群** Best-fit Customer（最受益的客群）
5. **市場分類** Market Category（你要被歸到哪個類別）

**輸出格式**：
```
STP 分析：

【Segmentation 切分結果】
- Segment A：[描述]，規模 ≈ X
- Segment B：[描述]，規模 ≈ X
- Segment C：[描述]，規模 ≈ X

【Targeting 評分】
| Segment | 規模 | 成長性 | 競爭強度 | 匹配度 | 可觸達 | 總分 |
|---------|------|--------|---------|--------|--------|------|
| A | 5 | 4 | 3 | 5 | 4 | 21 |
| B | 3 | 5 | 5 | 3 | 5 | 21 |
| C | 4 | 3 | 2 | 4 | 3 | 16 |

選定目標：Segment A（理由：[匹配度 + 規模]）

【Positioning 敘事】
- 我們是 [Market Category] 中的 [Unique Attribute] 替代方案
- 對標 [Competitive Alternatives]，我們的 [Unique Attribute] 帶來 [Value]
- 最受益的 Best-fit Customer 是 [Description]

一句話定位：「對 [Best-fit Customer] 而言，我們是 [Market Category] 中 [唯一/最好的] [Unique Attribute] 選擇，因為 [Value]」

信心評級：🟢/🟡
```

### 13.3 獲客漏斗 AARRR（Pirate Metrics，Dave McClure）

**用途**：從獲客到變現的五階段漏斗，量化每階段轉換率，找瓶頸。

**五階段**：
- **Acquisition 獲客**：訪客來源 + 量級
- **Activation 啟用**：完成首次「Aha moment」的比例
- **Retention 留存**：D1/D7/D30 回訪率
- **Referral 推薦**：NPS + 轉介率
- **Revenue 變現**：付費轉換 + ARPU + LTV

**操作方法**：
1. 抓自家 5 階段數據（或從第三方競品分析工具如 Similarweb 抓競品）
2. 對標同業中位數
3. 找轉換率最低的階段 → 那是優先優化點

**輸出格式**：
```
AARRR 漏斗（時間：[YYYY-MM]）：

| 階段 | 自家數字 | 同業中位數 | Gap | 優先級 |
|------|---------|-----------|-----|--------|
| Acquisition | X 訪客/月 | Y | +/-Z% | 🟢/🟡/🔴 |
| Activation | A% 首次啟用 | B% | +/-C% | 🟢/🟡/🔴 |
| Retention D7 | A% | B% | +/-C% | 🟢/🟡/🔴 |
| Retention D30 | A% | B% | +/-C% | 🟢/🟡/🔴 |
| Referral (NPS) | X | Y | +/-Z | 🟢/🟡/🔴 |
| Revenue (LTV/CAC) | A | B | +/-C | 🟢/🟡/🔴 |

最大瓶頸：[階段] — Gap = [數字]
建議優化動作：[具體建議]
信心評級：🟢（自家數據）/ 🟡（第三方推估）
```

### 13.4 競品行銷策略對標（Marketing Mix 4P + 訊息對比）

**用途**：拆解 2-3 個競品的行銷組合，找差異化切入點。

**操作方法**：
- **Product 產品**：核心功能、UX、定位
- **Price 價格**：定價模式（免費增值/訂閱/一次性/分潤）+ 價格錨點
- **Place 通路**：通過哪些通路觸達用戶（App Store / 直銷 / 通路商）
- **Promotion 推廣**：行銷訊息、廣告語、社群策略

**輸出格式**：
```
競品行銷組合對標：

| 維度 | 自家 | 競品 A | 競品 B | 差異化切入 |
|------|------|--------|--------|-----------|
| Product 核心賣點 | [描述] | [描述] | [描述] | [自家獨特處] |
| Price 定價 | [模式 + 價] | [模式 + 價] | [模式 + 價] | [錨點策略] |
| Place 通路 | [清單] | [清單] | [清單] | [未覆蓋通路] |
| Promotion 訊息 | [一句話] | [一句話] | [一句話] | [反向定位機會] |

切入點建議：[1-2 個競品忽略的角度]
信心評級：🟢/🟡
```
